1 · Intro

When to use it.

Costing tells Oracle which costing strings pay for a person's salary. Each payroll run turns pay into costing results that move to the General Ledger, so wrong costing means wrong department, grant, and project financials.

Fixing costing after payroll runs takes a retro cost transfer, so getting it right up front saves everyone time.

Use this whenYou set up or review costing for a hire, transfer, or funding change, or a FUM (financial unit manager) questions where salary was charged.

How employee costing impacts payroll and financial reporting

Use when: You set up or review costing for a hire, transfer, or funding change, or a FUM (financial unit manager) questions where salary was charged. · System: Oracle HCM

  1. Costing is set in Costing for Persons.
  2. Oracle uses the most specific level first: element, then assignment, then work unit default.
    • Element > Assignment > Work unit default
  3. Payroll creates costing results, then transfers them to the General Ledger.
  4. Costing must be right before payroll runs.
  5. Costing follows a person who transfers business units (BUs).
  6. After payroll runs, a retro cost transfer (RCT) is needed.
  7. Check your area with the Departmental Playbook reports.

Watch-outs

  • After a business unit transfer, costing does not reset on its own. Review it every time.
  • Blank costing on an assignment is not wrong by itself; the work unit default applies. Confirm the default is where the pay should go.
  • Open item: confirm the criteria for retro cost transfers and the deadline to fix costing before a payroll run. This covers more than grant labor.
