# HCM Academy

The landing page for Vanderbilt's HCM Academy: what the HCM role is, what the
Academy is for, and the topics with their courses.

Built with the Vanderbilt FLH course builder pattern, matching Working Smarter
(`me5231979/Course_Library`, `learn/index.html`): same colors, type, header,
hero, and footer. One self-contained HTML file, no framework,
no build step, no backend. Fonts and lockups live in `assets/`.

## Structure

Kept deliberately short:

1. **Hero**: what an HCM is (people embedded in the business who own the people work for their area) and what the Academy is for: learn, share, meet, get answers.
2. **Choose a topic**: a progress panel, a search box that searches every topic, and a row of horizontal topic tabs (built from the cards, so a new card gets a tab automatically; its `data-short` attribute is the tab label, and each tab shows its completed/total count). One topic shows at a time, full width, with training topics and job aids side by side. There are eight topics (Start Here plus seven topic areas). Each card, or each subsection in it, lists its training topics. 01 Positions, Recruitment & Hiring covers position management, staff hiring, and regional and out-of-state hiring (placeholder until EC provides details); 03 Assignments covers changes for current employees, transfers and promotions (requisition vs. no requisition), and offboarding; 06 holds all student and faculty hiring. Job aids are not listed separately: every course carries its own printable job aid.
   Below the cards, a one-line "HCM Playbook" strip marks where quick references will live (coming soon). Planned resource types: decision trees, process maps, scenario exercises, an FAQ, and fixes for common errors.
3. **Footer**: contact and accessibility statement.

## Assessments and completion

The assessments are their own pages, not pop-ups, so they can be linked, bookmarked, and later packaged for Oracle like the courses.

- Questions live in `assets/assessments.js` (one file for the assessment pages and the review document). Each question has a topic (the card id), the options, the correct option, optional feedback, and `draft: true` when its topic has no course yet and an SME must confirm it.
- **Pre-assessment** (`assessment/pre/`): the first row in Start Here, under "Begin here". 16 questions, two per topic, not graded. Results list the topics with a missed question, each linking to that topic's tab. The row shows "Taken" afterward.
- **Locked until the pre-assessment**: every course row shows "Locked" and points back to the pre-assessment until it has been taken once; a course page opened directly shows a locked message. Mark all complete (demo) also marks the pre-assessment taken.
- **Course completion**: passing a course's knowledge check (three questions, four on one course) marks it complete. Rows without a course yet are click-to-complete stand-ins.
- **Final assessment** (`assessment/final/`): the button in the progress panel links to it once every course is complete; before that, the page shows a locked message. 24 questions; 90% (22 of 24) marks HCM Academy complete. Below that, results list the topics to review and offer a retake. Answer order is shuffled each time. Pass mark: `pass` in `assets/assessments.js`.
- The assessment pages are generated by `python3 tools/build_courses.py` (same template as the courses). The build inlines `assets/assessments.js` and `assessment/assessment.js` into each page, so a cached page always has matching questions. Rebuild after editing either file.
- **Demo controls** in the progress panel: Mark all complete, Reset demo.
- On the public site, progress is saved only in this browser (`localStorage` keys `hcm-pre`, `hcm-done`, `hcm-final`, and `hcm-total`, the course count the landing page writes for the final's lock); nothing is sent anywhere. In the SCORM package it is saved in the LMS (see SCORM package below).
- **Review document**: `node tools/build_assessment_doc.cjs` rebuilds `docs/HCM_Academy_Assessments_Draft.docx` from the same questions, with answers, Approve/Edit/Remove checkboxes, and notes boxes.

## Course rows

Every course, job aid, and resource is a row with a title, a one-line overview,
time (or length), format (or type), and status. Overviews, times, and formats are
placeholder estimates written for the mock-up, except formats carried over from the
current catalog (videos and e-learning). Edit them in place: each row is
`<span class="tt">Title</span><span class="ds">Overview</span>` then
`<span class="tm">Time</span>` and `<span class="fm">Format</span>`.

## Micro-courses (V.02 draft)

68 short courses live in `courses/<slug>/`. Each has four parts: a brief intro,
a step-by-step walkthrough (a checklist where each step has a plain-language explanation
and the course ends with links to official Oracle or UKG documentation), a short knowledge check with
feedback, and a printable one-page job aid (Print button; print CSS shows only
the job aid). Answering every question correctly marks the course complete on the
landing page (shared `localStorage` key `hcm-done`, id `c-<slug>`).

- Every landing row is a micro-learning course (format "Micro-learning", 3 to 10 minutes).
- Courses drafted from Oracle documentation and official sources (not SME sessions) live in
  `tools/courses_researched.py` (slugs in `PARKED_R` stay as unbuilt drafts; their rows stay Coming soon); each shows a draft note and a Screen check list until a
  Vanderbilt SME reviews it.
- Content lives in `tools/course_content.py`. Edit there, then run
  `python3 tools/build_courses.py` to regenerate every page. The script also
  updates each course's row on the landing page (name, overview, time).
- Shared look and behavior: `courses/course.css`, `courses/course.js`.
- **Videos**: to start a course with a Guidde (or other) embed, add
  `video=dict(src="<embed URL>", title="<what it shows>")` to that course in
  `tools/course_content.py` and rebuild. The video appears at the top of the
  intro (16:9, full width, hidden when printing) and the course header lists
  "Video". First one: Weekly time card check.
- **Detailed job aids**: a course can add `detailed=dict(title, source, steps=[dict(t, d, img)])`
  with screenshots in `courses/<slug>/img/`. The one-page job aid becomes the
  **Quick guide** and the detailed job aid follows it (its own print pages).
  Two print buttons: quick guide only, or both. First one: Weekly time card
  check, from the Guidde walkthrough. Blur names, employee IDs,
  usernames, and assignment numbers in any screenshot before adding it; the
  site is public.
- Sources: HCM, costing, and payroll SME sessions (Oct 19 and 20); HCM training
  sessions 1 and 2 (Sep 8 and 9, 2026) for positions, requisitions, and pending worker conversion;
  no individual names are published on the site; the Costing for Persons guide (2022); the Document Records
  guide; the Award Compensation Elements guide (2023). Open items are flagged
  in each course's draft note and watch-outs.
- Landing rows link to a course with `data-course="<slug>"` on the `<li>`.

## V.02 draft: standard checks, owners, and a change log (November 2026)

Wrong or incomplete data in a hire or a pay change reaches payroll. V.02 adds what the guidance
needs to prevent that: standard documents and checks for pay-impacting transactions, an owner and a
change history on every course, cutoffs, the time card approval rule, and pay rules. All of it is a
draft. Everything Vanderbilt has not confirmed is marked **To confirm** or listed as an open item;
nothing is guessed.

- **One source: `tools/governance.py`.** Owners by area, the edition and update date, the change log,
  and the "Before you submit" data (what to attach, what to check, the cutoff, who does what) for
  24 pay-impacting courses. The course pages, the Playbook, and the section audit workbook all read it.
- **Owner on every course.** Owners are teams, shown at the top of the course, on the job aid, and
  in the Course record at the bottom. Payroll owns all payroll and financial topics (payroll, time
  cards, pay changes, the payroll calendar, costing). HRIS owns everything else (recruiting and
  hiring, assignment changes, offboarding, leave, records and reporting, the foundations). No
  individual names are published;
  the contact for each team is in an owner register kept outside this repository. The mapping is
  `owner()` in `tools/governance.py`: by topic, with a few courses set by slug.
- **Before you submit.** A block in the walkthrough and three lines on the job aid of each
  pay-impacting course. Document status is what the course says today (Required, Attach, If finance
  asks, To confirm), not yet one confirmed standard. Time card courses title it "Before you approve"
  or "Before you save".
- **Course record and What changed.** Each course ends with its owner, version, review status, and
  change log. `changes/index.html` lists changes across courses by date and the owners by area; it is
  linked from every course and from the strip under the topics on the landing page. To add a
  hand-written entry, use `EXTRA_CHANGES` in `tools/governance.py`.
- **New courses** (`tools/courses_v02.py`): What to attach (a table by transaction) and Who owns
  what (a table by transaction), both generated from `tools/governance.py`; Pay rules (overtime,
  holidays, shifts, on-call; federal rules from DOL sources, Vanderbilt's own rules are open items);
  Common pay errors (the errors the courses warn about, to be ranked from Payroll's list). The Shared
  Administrative Calendar draft is released from `PARKED_R`.
- **Time card approval.** The three time card courses say that the person who submits a time card
  does not approve it, as an open item for Payroll to confirm. Review and approve time cards has a
  fourth question on it.
- **Final assessment.** Four questions added (time card approval, a change pending at the cutoff, your
  part in a pay error, what to attach); two are marked `draft` until the rules are confirmed.
- **Owners set to teams (Nov 13, 2026).** V.02 first showed two owners, Payroll and Finance and
  Recruiting and Hiring, and left 30 courses with no owner. Every course is now owned by Payroll or
  HRIS, and each course logs the change.
- **Facts from Vanderbilt's published pages (Nov 13, 2026).** The Shared Administrative Calendar course is
  built from the HR/Payroll Calendar PDFs for 2026 and 2027 (People Experience site, Pay Calendar page).
  The monthly cutoff, time card deadlines, and off-cycle runs in other courses were corrected from the
  same source, and the FERPA course carries the directory information list from the Vanderbilt Student
  Privacy Statement. `PUBLISHED` in `tools/governance.py` logs each change. Re-read the calendar when a
  new one is posted: the 2027 calendar adds a Semi Monthly payroll and lists no off-cycle runs.
- **Open items are asked once.** `fold_items` in `tools/governance.py` folds near-duplicate open items
  in the section audit workbook, so a reviewer answers each point one time.
- **Still to decide** (not something a build can settle): how
  often courses are reviewed, who sends the notice when a pay-impacting course changes, and Payroll's
  list of the errors it corrects most.

## SCORM package (for Oracle Learning or another LMS)

```
python3 tools/build_courses.py
python3 tools/build_scorm.py
```

This writes `dist/HCM_Academy_SCORM_1.2.zip` and `dist/HCM_Academy_SCORM_2004.zip` (SCORM 2004 4th Edition). `dist/` is not committed: rebuild after any course change and upload the new zip.

- **One SCO, the whole academy**: landing page, 68 courses, pre-assessment, final assessment, Playbook, and What changed. `scorm.html` is the launch page. It connects to the LMS and shows the academy in a frame.
- **How progress is saved**: every page in the package loads `scorm/bridge.js` first. Inside the launch page, the pages save to the LMS (`cmi.suspend_data`) instead of the browser. Outside it, nothing changes. The public site never loads the bridge.
- **What the LMS receives**:
  - Status: incomplete until the final assessment is passed, then passed (1.2) or completed and passed (2004), with the score (best passing score, out of 100). A failed final leaves the course open for a retake.
  - Objectives: one per course (completed), plus the pre-assessment (score) and the final (score, passed or failed). The pre and final scores can be compared.
  - Interactions: every assessment answer, by question number, as a letter in the question's original option order.
  - Progress (2004): courses complete out of 68, plus the final.
  - The last page viewed (relaunch opens it), session time, and exit "suspend" so a learner can come back to the courses as a reference.
- **Mastery score**: taken from `pass` in `assets/assessments.js` (90% today) and written into the manifest.
- **Package-only changes**: folder links point at `index.html` (LMS file servers often do not serve folders); the Mock-up buttons are hidden; the 15 rows with no course yet are shown but do not count, so completion means all 68 courses; pages outside the package open in a new tab.
- **Checks in the build**: every link and asset must resolve inside the package; the longest progress record must fit SCORM 1.2's 4,096 characters; the manifest must be well-formed. The schema files in `tools/scorm/xsd/` go into each zip.
- Opened without an LMS, the launch page says it is not connected and keeps progress in the browser.
- When the LMS opens the course in a small pop-up window, the launch page resizes that window to fill the screen (browsers allow this only for pop-ups). For the LMS setting, see the launch window options in the LMS (SCORM Cloud: Launch Behavior).

## HCM Playbook

Every course job aid combined into one branded, printable book: cover, how to use,
contents with page numbers, a divider for each topic, one page per quick guide (plus
the Weekly time card check detailed job aid), and a back cover.

- Web view: `playbook/index.html`; PDF: `playbook/HCM_Playbook.pdf` (linked from the
  HCM Playbook strip on the landing page once the pre-assessment is taken).
- Rebuild after any course change:
  `python3 tools/build_playbook.py && node tools/render_playbook.cjs`
  The renderer tightens type on any page that would overflow and reports pages that
  still do. Courses marked Pending SME review carry that tag in the playbook too.

## Topic audit PDF

`docs/HCM_Academy_Topic_Audit.pdf`: every topic, subtopic, and course topic with status,
source, time, and Keep / Change / Remove boxes plus note lines, for reviewers to mark up.
The PDF is a fillable form: 348 clickable checkboxes (Keep, Change, Remove, Merge; topic-level checks) and 169 text fields (Merge with, notes per course topic
and per topic, plus reviewer, area, and date).
Rebuild: `python3 tools/build_topic_audit.py && node tools/render_topic_audit.cjs && python3 tools/make_audit_fillable.py`
(the last step needs PyMuPDF: `pip install pymupdf`).

## Section audit workbook (sign up, then audit)

`docs/HCM_Academy_Section_Audit.xlsx` (built by `python3 tools/build_section_audit.py`):
Start here (instructions), Sign-up (up to five reviewer slots per section, a signed-up count, target date, status,
progress formula, section verdict), one tab per section with every course topic (Decision:
Keep / Change / Remove / Merge, Merge with, accuracy of steps, job aid, and quiz, notes,
priority, PCB status), the owner by area, open items including the Before you submit points to confirm,
and a Summary with live counts. Share it from SharePoint or OneDrive
so reviewers edit one copy.

## Explainer videos

Each video is a scripted scene in `tools/video/<process>.html`: Oracle HCM screens rebuilt in HTML (Vanderbilt header, Redwood pages), a cursor that clicks and types, a camera that zooms to the field in use, and on-brand captions. Names and data are fictional, and every frame carries a "Training simulation" tag. Steps, captions and watch-outs come only from the course's own content.

```
node tools/video/render.cjs direct-reports /tmp/silent.mp4            # frames; also writes /tmp/silent.segs.json
python3 tools/video/narrate.py direct-reports /tmp/silent.mp4 courses/direct-reports/video/direct-reports.mp4
node tools/video/stills.cjs direct-reports /tmp/stills                # job aid screenshots, one per mark()
python3 tools/build_courses.py
```

Narration: one ElevenLabs read of the script in `tools/video/narration/<scene>.json`, saved as `<scene>.mp3` and cut at the pauses between paragraphs. Each clip plays when its step starts, and the scene holds each step until its clip ends (`NARR` in the scene file holds the clip lengths). Change the script and you record the read again and update the cut points.

Open the scene file in a browser to preview it (space pauses). A course shows the video when its entry in the course data has `video` with an `.mp4` source and a poster.

- Section 1, Hiring: all 10 process courses (Compensation memo, Create a position, Update a position, Create a requisition, Background checks, Convert a pending worker, Rehires, Staff, Non-Workers, Executive or external search), plus Direct Reports in Assignment Changes. Each is narrated (voice: Sarah Explains), with captioned steps and a detailed job aid that has one picture per course step (on the course page and in the Playbook). Videos in Oracle use Vanderbilt's Our Workforce and Show More screens; the pages inside each flow follow standard Oracle and the course text, so check labels against Vanderbilt's Oracle (see each course's Screen check). Steps outside Oracle are shown as a process board.
